# Nightly Build 每日构建 — 实施方案

## 概述
新建一个工作流文件 `.github/workflows/nightly.yml`，每天北京时间 21:00（UTC 13:00）定时构建 Android TV APK + Windows 安装包，自动根据自上次 nightly 以来的提交生成 changelog，打 `nightly-YYYYMMDD` tag 并发 GitHub **预发布**（Pre-release）。**不 bump 版本号**，只在 runner 工作区临时把版本拼成 `0.1.3-nightly.20260819` 用于产物命名，绝不推回仓库。

## 关键决策
1. **版本号处理**：`prepare` 作业读 `package.json` 的 `version`（如 `0.1.3`）→ 拼 `0.1.3-nightly.20260819`。Android 作业用 `sed` 改 `build.gradle.kts` 的 `appVersionName`；Windows 作业用 node 改 `package.json` + `package-lock.json`。全部在 ephemeral runner 内，**不 commit、不 push**，仓库真实版本号不变。
2. **Tag 隔离**：用 `nightly-YYYYMMDD`，不匹配 `v*` → 不触发 `release.yml`（v* tag → 发 Gitee+推 update.json）也不触发 `ci.yml` 的 windows-build。仅 `ci.yml` 的 `on: push` 会因 tag 推送重跑一次 `checks`（无害 ~2min）。
3. **不污染正式更新流**：nightly 直接 `gh release create --prerelease`，**不调 `publish-release.mjs`、不写/推 `update.json`、不发 Gitee**。正式用户"检查新版本"读的是 master 的 `update.json`，完全不受影响。`compareVersions` 已验证：nightly 版本号在比较中"不小于"同 minor 正式版，nightly 用户不会被误弹更新提示。
4. **Changelog**：`git log <上一个 nightly tag>..HEAD --no-merges`（无 nightly tag 回退到上一个 `v*` tag，再无则取最近 50 条），写入 `changelog.md`，经 artifact 传给 release 作业用 `--notes-file`。定时触发时若 HEAD == 上一个 nightly tag 的 commit（无新提交）→ 跳过构建省额度；手动触发可 `force=true` 强制。
5. **Windows 用 `build:full`**（含 `bundle-python`）：nightly 安装包自带嵌入式 Python，beat/loudness/compensation 服务可真正运行，是完整可测包（比 ci.yml 冒烟构建多 5-8min）。
6. **Release 要求两端构建都成功**才发；手动重跑同一天幂等（tag 已存在则 `upload --clobber` + `edit --notes-file`）。
7. **并发控制**：`concurrency: nightly-build, cancel-in-progress: false`，避免重叠且不中断进行中的构建。

## 作业结构
- `prepare`（ubuntu）→ 输出 `nightly_tag`/`nightly_version`/`has_changes` + 上传 `changelog.md` artifact
- `build-android`（ubuntu，needs prepare，if has_changes）→ 复刻 ci.yml android-build 步骤 + 版本号注入 + APK 重命名上传
- `build-windows`（windows，needs prepare，if has_changes）→ 复刻 ci.yml windows-build + 版本号注入 + `bundle-python` + `build:electron` + 上传 `release/*.exe`
- `release`（ubuntu，needs 三者，if has_changes && 两构建 success）→ 下载 changelog + 两端产物 → `gh release create nightly-DATE --prerelease --notes-file changelog.md artifacts/*`（已存在则更新）

## 新建文件：`.github/workflows/nightly.yml`

```yaml
# 每日构建（Nightly）：每天北京时间 21:00 自动构建 Android TV + Windows 测试版。
# - 不 bump 正式版本号，仅在工作区拼 "<基础版本>-nightly.<YYYYMMDD>" 用于产物命名，不推回仓库。
# - 自动生成 changelog（自上次 nightly tag 以来的提交），打 nightly-YYYYMMDD tag 并发 GitHub 预发布。
# - 不写/推 update.json、不发 Gitee —— 不影响正式版检查更新与正式发版流程。
# 也可在 Actions 页面手动触发（force=true 可忽略"无新提交"跳过逻辑强制构建）。

name: Nightly Build 每日构建

on:
  schedule:
    # UTC 13:00 = 北京时间 21:00
    - cron: '0 13 * * *'
  workflow_dispatch:
    inputs:
      force:
        description: '强制构建（忽略「无新增提交」跳过逻辑）'
        required: false
        default: 'false'
        type: choice
        options: ['false', 'true']

concurrency:
  group: nightly-build
  cancel-in-progress: false

permissions:
  contents: write   # gh release create / 打 tag 需要

jobs:
  # ---------- 准备：日期 / nightly 版本 / changelog / 跳过判定 ----------
  prepare:
    name: 准备（日期/版本/Changelog）
    runs-on: ubuntu-latest
    outputs:
      nightly_tag: ${{ steps.meta.outputs.nightly_tag }}
      nightly_version: ${{ steps.meta.outputs.nightly_version }}
      has_changes: ${{ steps.meta.outputs.has_changes }}
    steps:
      - name: 拉取代码（完整历史，供查找上一个 nightly tag 与生成 changelog）
        uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: 安装 Node
        uses: actions/setup-node@v4
        with:
          node-version: 24

      - name: 计算日期 / nightly 版本 / changelog
        id: meta
        env:
          FORCE: ${{ github.event.inputs.force }}
        run: |
          # 北京时间日期作为构建标识
          DATE=$(TZ=Asia/Shanghai date +%Y%m%d)
          NIGHTLY_TAG="nightly-${DATE}"

          # 读取基础版本（package.json），不改仓库，只在工作区拼出 nightly 版本
          BASE_VERSION=$(node -p "require('./package.json').version")
          NIGHTLY_VERSION="${BASE_VERSION}-nightly.${DATE}"

          # 查找上一个 nightly tag；没有则回退到上一个正式 tag（v*）；都没有取最近 50 条提交
          LAST_NIGHTLY=$(git tag -l 'nightly-*' --sort=-creatordate | head -1)
          if [ -n "$LAST_NIGHTLY" ]; then
            RANGE="${LAST_NIGHTLY}..HEAD"
          else
            LAST_STABLE=$(git tag -l 'v*' --sort=-creatordate | head -1)
            RANGE="${LAST_STABLE:+${LAST_STABLE}..HEAD}"
          fi

          # 无新增提交判定（仅当存在上一个 nightly tag 且非 force 时生效）
          HAS_CHANGES="true"
          if [ "$FORCE" != "true" ] && [ -n "$LAST_NIGHTLY" ]; then
            if [ "$(git rev-parse "$LAST_NIGHTLY")" = "$(git rev-parse HEAD)" ]; then
              HAS_CHANGES="false"
            fi
          fi

          # 生成 changelog（排除 merge 提交，取 commit subject + 短哈希）
          {
            echo "# WaveForge Nightly ${DATE}"
            echo ""
            echo "**版本号：${NIGHTLY_VERSION}（基础 ${BASE_VERSION} + 构建日期，非正式发版，不自动升级版本号）**"
            echo ""
            if [ -n "$RANGE" ]; then
              echo "## 代码变动（${RANGE}）"
              echo ""
              LOG=$(git log $RANGE --no-merges --pretty=format:"- %s (%h)" 2>/dev/null)
              if [ -z "$LOG" ]; then echo "- 无新增提交"; else echo "$LOG"; fi
            else
              echo "## 代码变动（最近 50 条提交）"
              echo ""
              git log -50 --no-merges --pretty=format:"- %s (%h)"
            fi
            echo ""
            echo ""
            echo "---"
            echo "⚠️ 自动构建的每日测试版本，可能不稳定。仅用于测试，不推送 update.json，不影响正式版检查更新。"
          } > changelog.md

          echo "nightly_tag=${NIGHTLY_TAG}" >> "$GITHUB_OUTPUT"
          echo "nightly_version=${NIGHTLY_VERSION}" >> "$GITHUB_OUTPUT"
          echo "has_changes=${HAS_CHANGES}" >> "$GITHUB_OUTPUT"

          echo "::group::Changelog 预览"
          cat changelog.md
          echo "::endgroup::"
          echo "已计算：tag=${NIGHTLY_TAG} version=${NIGHTLY_VERSION} has_changes=${HAS_CHANGES}"

      - name: 上传 changelog（供 release 作业读取）
        uses: actions/upload-artifact@v4
        with:
          name: nightly-meta
          path: changelog.md

  # ---------- Android TV APK 构建 ----------
  build-android:
    name: Android TV APK 构建
    needs: prepare
    if: needs.prepare.outputs.has_changes == 'true'
    runs-on: ubuntu-latest
    timeout-minutes: 45
    steps:
      - name: 拉取代码
        uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: 安装 Node
        uses: actions/setup-node@v4
        with:
          node-version: 24
          cache: npm

      - name: 安装依赖
        run: npm ci

      - name: 写入 nightly 版本号到 build.gradle.kts（仅工作区，不推回仓库）
        env:
          NIGHTLY_VERSION: ${{ needs.prepare.outputs.nightly_version }}
        run: |
          sed -i "s|val appVersionName = \".*\"|val appVersionName = \"${NIGHTLY_VERSION}\"|" android/app/build.gradle.kts
          grep appVersionName android/app/build.gradle.kts

      - name: 拉取 nodejs-mobile 运行时
        run: npm run fetch:nodejs-mobile

      - name: 组装安卓资产（前端 + 后端 bundle + 设备端依赖）
        run: npm run build:android

      - name: 安装 JDK 17
        uses: actions/setup-java@v4
        with:
          distribution: temurin
          java-version: 17

      - name: 安装 Android SDK
        uses: android-actions/setup-android@v3

      - name: 安装 NDK / CMake / 平台
        run: |
          yes | sdkmanager --licenses > /dev/null 2>&1 || true
          sdkmanager "ndk;27.0.12077973" "cmake;3.22.1" "platforms;android-35" "build-tools;35.0.0"

      - name: 构建 APK（debug 签名）
        run: cd android && ./gradlew assembleDebug --no-daemon

      - name: 重命名 APK（带 nightly 版本号）
        env:
          NIGHTLY_VERSION: ${{ needs.prepare.outputs.nightly_version }}
        run: |
          cp android/app/build/outputs/apk/debug/app-debug.apk \
             "WaveForge-${NIGHTLY_VERSION}-tv-debug.apk"

      - name: 上传 APK
        uses: actions/upload-artifact@v4
        with:
          name: nightly-android-apk
          path: WaveForge-*-tv-debug.apk

  # ---------- Windows 安装包构建 ----------
  build-windows:
    name: Windows 安装包构建
    needs: prepare
    if: needs.prepare.outputs.has_changes == 'true'
    runs-on: windows-latest
    timeout-minutes: 60
    steps:
      - name: 拉取代码
        uses: actions/checkout@v4

      - name: 安装 Node
        uses: actions/setup-node@v4
        with:
          node-version: 24
          cache: npm

      - name: 安装依赖
        run: npm ci

      - name: 写入 nightly 版本号到 package.json + lock（仅工作区，不推回仓库）
        env:
          NIGHTLY_VERSION: ${{ needs.prepare.outputs.nightly_version }}
        run: |
          node -e "const fs=require('fs');for(const f of ['./package.json','./package-lock.json']){const j=JSON.parse(fs.readFileSync(f));j.version=process.env.NIGHTLY_VERSION;fs.writeFileSync(f,JSON.stringify(j,null,2)+'\n')}"
          node -p "require('./package.json').version"

      - name: 下载 Electron 运行时（npm ci 跳过了其 install 脚本）
        run: node node_modules/electron/install.js

      - name: 重建嵌入式 Python（让打包版自带 beat/loudness/compensation 服务）
        run: npm run bundle-python
        timeout-minutes: 20

      - name: 构建 Windows 安装包（electron-builder nsis）
        run: npm run build:electron
        timeout-minutes: 30

      - name: 上传安装包
        uses: actions/upload-artifact@v4
        with:
          name: nightly-windows-installer
          path: release/*.exe

  # ---------- 发 tag + 发布 GitHub 预发布 ----------
  release:
    name: 发 tag + 发布 GitHub Pre-release
    needs: [prepare, build-android, build-windows]
    if: ${{ needs.prepare.outputs.has_changes == 'true' && needs.build-android.result == 'success' && needs.build-windows.result == 'success' }}
    runs-on: ubuntu-latest
    steps:
      - name: 拉取代码（供 gh release 打 tag 到当前 master HEAD）
        uses: actions/checkout@v4

      - name: 下载 changelog
        uses: actions/download-artifact@v4
        with:
          name: nightly-meta

      - name: 下载 Android APK
        uses: actions/download-artifact@v4
        with:
          name: nightly-android-apk
          path: artifacts

      - name: 下载 Windows 安装包
        uses: actions/download-artifact@v4
        with:
          name: nightly-windows-installer
          path: artifacts

      - name: 创建 tag + 发布 Pre-release（已存在则更新，支持手动重跑幂等）
        env:
          NIGHTLY_TAG: ${{ needs.prepare.outputs.nightly_tag }}
          GH_TOKEN: ${{ github.token }}
        run: |
          ls -la artifacts
          if gh release view "$NIGHTLY_TAG" >/dev/null 2>&1; then
            echo "release 已存在，更新产物与 changelog"
            gh release upload "$NIGHTLY_TAG" artifacts/* --clobber
            gh release edit "$NIGHTLY_TAG" --notes-file changelog.md --prerelease
          else
            gh release create "$NIGHTLY_TAG" \
              --title "WaveForge Nightly $(echo $NIGHTLY_TAG | sed 's/nightly-//')" \
              --notes-file changelog.md \
              --prerelease \
              --target master \
              artifacts/*
          fi
          echo "已发布 $NIGHTLY_TAG（预发布，不覆盖正式 latest）"
```

## 正确性保证
- **正式版本号不动**：所有版本号修改都在 runner 工作区，无任何 git commit/push 回 master。
- **正式发版/更新流不受影响**：nightly 不调 `publish-release.mjs`、不写 `update.json`、不发 Gitee；tag 用 `nightly-*` 命名空间不触发 `release.yml`/`ci.yml` 的 `v*` 条件。
- **"检查新版本"无误报**：已验证 `compareVersions` 把 `0.1.3-nightly.20260819` 当作 ≥ `0.1.3`，nightly 用户不会被同 minor 正式版误弹提示；正式版升 minor/patch 后正常提示。
- **预发布不抢 latest**：`--prerelease` 标记，GitHub 不会把 nightly 设为 latest。

## 可选后续（不在本次范围）
- 若想消除 nightly tag 推送导致 `ci.yml` 重跑 `checks` 的冗余，可在 `ci.yml` 的 `on.push` 加 `tags-ignore: ['nightly-*']`（一行）。
- 若希望某一端构建失败时仍发布另一端产物，把 release 的 `if` 放宽为 `needs.build-android.result == 'success' || needs.build-windows.result == 'success'` 并按结果决定上传哪个 artifact。

执行时只需创建上述单个文件 `.github/workflows/nightly.yml`，无其他仓库改动。
