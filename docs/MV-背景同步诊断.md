# MV 背景同步诊断（[renderer:MvSync]）

排查「MV 背景歌词比 App 歌词快/慢一句」类反馈的专用诊断。日志写在
`automix-backend.log`（Electron userData 目录），渲染进程经 `automixLog('MvSync', …)`
上报，行首为 `[AutoMix-Backend][renderer:MvSync]`。

## 日志 tag 一览

| tag | 内容 | 产生位置 |
|---|---|---|
| `[renderer:MvAlign]` | 事件流：匹配完成（含评分/类型/CC）、对齐成功/命中缓存（offset/conf/method）、seek跟随、跳转对齐、补偿细节 | mvAlignment / BilibiliMvBackground |
| `[renderer:MvSync]` | **状态流**：跟踪开始 + 心跳 —— 把歌曲、视频、对齐、位置、歌词行的同时刻对应关系说全 | BilibiliMvBackground 同步循环 |

## MvSync 行格式（字段顺序固定，便于 grep/diff）

```text
跟踪开始 song=qq:330436570 "Dead Inside" 视频="Dead Inside-АДЛИН…" 槽=A 候选=other/unverified bvid=BV11G4y1m7Gc 对齐=offset=1.5s conf=0.55 method=envelope audio=24.93s video=26.43s 漂移=+0.00s 歌词行="Сижу среди четырёх стен"@24.5s 校正=0
心跳 song=… audio=34.93s video=36.43s 漂移=+0.02s 歌词行="…"@30.1s 校正=1
```

- **跟踪开始**：(歌曲, 视频, 对齐态) 任一变化时打一行，宣告本次跟踪的完整映射。
  对齐态从 `free` 变 `aligned`（对齐算完/缓存命中）会再补一条，宣告最终映射。
- **心跳**：播放中每 10s 一行；缓冲/seeking 期间也照打（此时 video 位置可能停着不动，
  正是要观察的事实）。

### 字段说明

| 字段 | 含义 |
|---|---|
| `对齐=` | `offset/conf/method`（已生效）；`有缓存但置信不足(<0.5/…) → 自由播放`；`无 → 自由播放` |
| `生效偏移` | 对齐可信时视频位置 = 音频位置 + offset；未生效时按 0 自由跟随 |
| `漂移` | `video − (audio + 生效偏移)`，理想 ≈ 0；超过 ±3s 且冷却到期会触发 seek 校正（`校正` 计数 +1） |
| `歌词行` | 音频位置所在的本地歌词行及行时间（无歌词/首行前为空缺省） |
| `候选` | 候选类型/CC 验证（official/lyrics/live/cover/other；match/mismatch/unverified） |

### 包络对齐的峰突出度（prominence）

`method=envelope` 的偏移来自 MV/歌曲 RMS 包络的互相关，其可信度由**双门槛**裁决
（`buildEnvelopeAlignment`）：绝对峰值 ≥ 0.6 **且** 峰突出度 ≥ 0.05（主峰 − ±2s 外次峰）。
置信度按证据分级（`0.4 + (peak−0.6) + prominence×2`，封顶 0.8），不再是硬编码 0.55。

为什么要突出度：phonk 等高度重复结构的相关曲线平坦，±2s 外常有几乎等高的竞争峰，
argmax 落在哪个重复段近似抛硬币（实测 Одна 绝对峰值 0.67、偏移却错 ~4-5s ≈ 一句歌词；
构造用例里甚至落在与真值差 25s 的等价峰上）。突出度不足 → 拒绝对齐（自由播放），
在 `[renderer:MvAlign]` 里表现为 `包络兜底拒绝` / `媒体元素包络对齐拒绝`。

## 判读方法

1. **漂移 ≈ 0 而用户仍看到背景快/慢一句** → 视频位置本身正确，是**视频内嵌字幕的
   时间轴与该视频自己的音频不符**（上传者制作问题，如内嵌歌词整体提前/变速转载）。
   系统侧无错，处理方式是候选条手动换官方/字幕视频。
2. **漂移大（>3s）且 `校正` 不增长** → 同步循环没校正：查 `对齐=` 是否自由播放
   （自由播放也会按 offset=0 跟随，不应长期漂移）、是否冷却被占用、视频是否反复缓冲。
3. **切歌后短时间错位** → 看切歌时刻附近有没有 `跟踪开始` + 校正；新视频落槽会清空
   校正冷却，正常应在 ≤1.5s 内就位（实测旧版曾被上一首的冷却挡住 ~4.5s）。
4. **`对齐=` 显示 `有缓存但置信不足`** → 该视频曾被信号链否决（节拍网格/包络/字幕），
   自由播放是有意行为；若怀疑误杀，对照 `[renderer:MvAlign]` 的拒绝原因日志。
5. **`回退封面 进入 status=none/error`** → MV 层整体让位给封面（背景"没了"的直接原因）。
   - `status=none`：搜索无匹配（含兜底失败）——查其前的 `匹配完成` 行；
   - `status=error`：匹配失败或视频播放失败——查其前的 `加载失败`（含原因）与
     `视频error`（含槽位/bvid）行；候选链耗尽会连续出现多条。
   回倒/快速切歌后"背景没了"，把 `回退封面` 行前后 20 行发出来即可定位是哪一环。

## 已知局限

- 视频内嵌字幕的时间轴系统不可见（在像素里），诊断只能证明「视频位置 ↔ 音频位置」
  的映射是否正确，内嵌字幕错位需人工看片头/片尾对照。
- 心跳只覆盖背景层（播放页/歌词页 MV 背景）；看歌模式的 DASH 音画同步由
  BilibiliMvPlayer 自行管理，仅在对齐计算时共享 `[renderer:MvAlign]` 事件。
